# ECHO: how every session works

ECHO asks whether recommendation policies can change exposure and simulated taste rather than simply reflect it. The authority is `master_prompt.md`. Never edit it. If this file and the master prompt conflict, the master prompt wins. The one recorded exception is the licence (see `research/decision_log.md`, DEC-001).

## 1. Reading order (mandatory, before modifying anything)

1. `master_prompt.md`
2. `roadmap.md`
3. `progress.md`
4. `research/protocol.md`
5. `research/claims_register.csv`

Then run `git status` and inspect the existing files. Never overwrite owner changes. At session start, state the current milestone and the next bounded task.

## 2. Mandatory requirements (master prompt section 11)

- Keep `research/experiment_registry.csv` current. Every planned experiment gets a stable ID (EXP-NNN) before execution, with purpose, dependency, primary outcome, protocol hash, status, report location and planned analysis. Seeds are runs inside an experiment, not separate experiments.
- Before an experiment runs, `research/experiments/EXP-NNN/protocol.md` exists and follows section 11.2. Confirmatory runs need a frozen protocol (version and SHA-256 hash recorded) and the owner's recorded approval.
- Every registered experiment gets a standalone report `research/experiments/EXP-NNN/report.md` with the 12-part structure of section 11.3, including failed, null, abandoned and exploratory experiments. Reports link to their own machine-readable outputs.
- One integrated manuscript, `research/paper/manuscript.md` (canonical source), with `manuscript.tex` generated by pandoc and the PDF generated locally (pandoc to Typst, compiled with the typst Python package). Never claim a PDF exists unless it was generated and inspected.
- `research/publication/` holds the artifact manifest, claims audit, reproducibility report, author review and release checklist.
- Tables and figures are generated from versioned results by script, once, and reused in reports, manuscript, demo and articles. Every number maps to experiment ID, run IDs, metric definition, result path, generator script, config or protocol hash and code revision.
- A second review pass challenges the preferred hypothesis. AI review is internal quality control, not peer review.
- Milestone additions (11.6): M0/M1 registry, manuscript skeleton, experiment protocols, zero-cost toolchain, freeze before execution. M2 versioned output schemas, manifests and report generators alongside the core. M3 reports written as experiments finish, all failures and deviations recorded. M4 reports and evidence audit finished, manuscript synthesis with contradictory results and sensitivity analysis. M5 demo, paper, reports and articles use identical verified results. M6 PDFs compiled and inspected, references and links verified, clean-clone smoke reproduction, owner review checklist.

## 3. Gates

- **G-PUBLIC.** Never push, add a remote, create a GitHub repository or publish anything.
- **No paid service** of any kind: no paid API, inference, dataset, compute, hosting or domain. Do not use the coding subscription as an inference backend.
- **G-FREEZE.** Never freeze a protocol yourself. Freezing is the owner's decision. Until then, runs are exploratory and labelled as such.
- No confirmatory experiments before the owner freezes the protocol. Small exploratory smoke checks are allowed and labelled exploratory.

## 4. Scope

- Work only inside this repository. Read-only use of the shared tools is allowed (paths relative to this repository):
  - `../.tools/py/bin/` (uv, python with typst, pypdf, pillow)
  - `../.tools/pandoc`
  - `../../helix/.tools/node/bin` (read-only; never modify that folder)
  - `/usr/local/bin/python3`, git.
- Do not touch any other folder under the parent research folder (`../..`).
- Never kill processes you did not start. Never delete anything you did not create in the current session.

## 5. Truthfulness

- Never fabricate results, citations, test counts or PDFs.
- Record commands and their actual outputs in `progress.md`.
- Anything not verified is labelled unverified. Cite a source only if it was actually opened, with URL or DOI and access date.
- Simulated preference change is not evidence of human persuasion. No Spotify scraping, no licensed audio distribution.

## 6. Files and style

- New text and code files start with `SPDX-License-Identifier: LicenseRef-ECHO-NC-Research-1.0` as a comment where the format allows. JSON and CSV are covered by `NOTICE.md`.
- Do not change the licence files (`LICENSE`, `NOTICE.md`, `LICENSE_HISTORY.md`, `CLA.md`, `.github/`). Development commands may be appended to `CONTRIBUTING.md`.
- English. No em dashes. Plain, formal register.
- No e-mail address, personal identifier or secret in any committed file (git author metadata excepted).
- Refer to the owner as "the owner" (they/them).
- Commits are local only, made with the owner's git identity (user name `mohamedbechirkefi`; the e-mail is supplied on the command line with `git -c user.email=...`, never written into a file). The message ends with a blank line, then the Co-Authored-By trailer for the assisting model. Run `git status` before and after.

## 7. Session end

Update `roadmap.md` and `progress.md` (append-only, dated, with commands and real outputs, failures, changed files, risks, next action). Never mark incomplete work done.
