## DEC-005 (2026-11-24): Primary baseline and metric (PROPOSED, awaiting owner freeze)

- **Decider:** the AI proposes; the owner decides at freeze.
- **Proposal:**
  - Baseline: uniform-random recommendation (RAND). It is the simplest policy and does not use the listener's profile, so it is the natural "no steering" reference for induced shift (in the spirit of carroll2022).

## DEC-006 (2026-11-24): M2 implementation choices not fixed by the draft protocol (PROPOSED, awaiting owner confirmation at freeze)

- **Decider:** the AI proposes; the owner confirms or replaces them at freeze.
- **Context:** Draft protocol v0.1 leaves some model details open. The M2 code needs concrete values, so it uses the defaults below. They are recorded in every result file (`config`) and covered by the config hash.
- **Choices:**
  - Cluster geometry: K cluster centres are random unit vectors; a track is `normalise(centre + 0.1 * N(0, I_d))` with a uniformly random cluster (`track_spread = 0.1`); a listener's initial taste is `normalise(centre + 0.1 * N(0, I_d))` around a uniformly random centre (`listener_spread = 0.1`).
  - Skip option utility: `skip_utility = 0.0` in cosine units (the skip logit is 0 / tau).
  - Base popularity: Zipf weights `rank^(-s)` over a random permutation of ranks, scaled to sum to N, so POP scores are `consumption count + base popularity` on comparable scales.
  - Warm-up: SIM, MMR and EXPLORE show RAND slates for the first `warmup_steps` steps and whenever the listener has no consumed track yet; the same rule applies with the oracle profile so that the oracle ablation only changes the profile. POP and RAND have no warm-up.
  - Timing of POP counts: all listeners move one step at a time; counts are updated after every listener has chosen at step t.
  - EXPLORE: each slot is random with probability epsilon (flag drawn per slot); random slots follow the RAND key order, SIM slots the SIM order, without duplicates.
  - MMR: the first pick is argmax relevance; later picks maximise `lambda * rel - (1 - lambda) * max cos to the slate`, over the whole candidate set.
  - Per-listener averages over consumed tracks (novelty, relevance, drift per accepted item) are averaged over listeners with at least one acceptance. A run where no listener accepts has non-finite metrics and is recorded as failed, as protocol section 5 requires.
  - Drift is computed as `2 * arcsin(||p_0 - p_T|| / 2)`, which equals the protocol's `arccos(clip(<p_0, p_T>))` for unit vectors but is exactly 0 for identical vectors (needed for check V2) and accurate near 0. A property test checks agreement with the arccos form to 2e-7 rad.
  - Common random numbers: the seed spawns four streams (catalogue, listeners, choice uniforms, policy keys); the policy stream draws the same amount every step for every policy.
  - The protocol's decision rule does not name the case where the CI excludes 0 and also lies inside [-SESOI, SESOI]. The code reports it as "reject H0, smaller than SESOI". The owner should state the intended reading at freeze.

## DEC-012 (2026-11-25): Confirmatory analysis code and open analysis choices, fixed before any confirmatory output

- **Decider:** the AI, under the M3 brief (`labs/_shared/M3-brief.md`); open choices flagged for the owner's ratification. Written and committed before any EXP-002, EXP-003 or EXP-004 output existed.
- **Context:** the frozen protocol fixes the estimand, the bootstrap (95 % percentile, 10,000 resamples, seed 7), the paired t interval, d_z, SESOI 0.05 rad, the decision rule, the negative control, the stop rule, the EXP-003 robustness rule and the EXP-004 replication reading. The M2 code implemented only the exploratory pilot summary; Holm adjustment was deferred to M3 (roadmap M2). The confirmatory analysis is now `src/echo/analysis.py`, tested in `tests/test_analysis.py`.
- **Choice 1, Holm-adjusted intervals (protocol section 5: "Holm-adjusted intervals for the four drift contrasts").** The protocol does not say which p-values or which interval construction. Fixed here: the family is the four adaptive drift contrasts SIM, POP, MMR and EXPLORE minus RAND (protocol section 5 says four; the EXP-002 protocol item 14 lists the three secondaries, and the primary decision still uses the unadjusted 95 % CI as the decision rule says). p-values are two-sided bootstrap p-values from the same 10,000 resamples, p = min(1, 2 min(P(mean* <= 0), P(mean* >= 0))). Holm step-down at alpha 0.05; the contrast with rank i of m gets a percentile bootstrap interval at level 1 - 0.05 / (m - i + 1). For EXP-003 the family is the 18 cells (item 14: "Holm-adjusted intervals are also reported"); they do not enter its decision rule. For EXP-004 the family is the same four contrasts.
- **Choice 2, "practically equivalent" in the EXP-003 withdrawal rule and the EXP-004 reading.** After protocol 10.2 item 4, a CI inside [-SESOI, SESOI] that excludes 0 has its own label ("statistically detectable, practically negligible"). Whether such a cell counts as "practically equivalent to 0" in EXP-003 item 4 and protocol 10.1 is not stated. Both readings are computed: the band reading (CI inside the band) and the label reading (decision label exactly "practically equivalent"). If they give different verdicts the report states both and the verdict is "readings disagree: owner decision needed"; nothing is chosen after seeing data.
- **Choice 3, the oracle versus estimated check (protocol section 7).** "Differs in sign" is reported two ways: point-estimate signs, and both CIs excluding 0 with opposite signs.
- **Descriptive secondaries:** per-arm seed-level means with 95 % percentile bootstrap CIs for all ten metrics, and seed-paired differences versus RAND, labelled descriptive (protocol section 5).
- **Provenance:** per-run manifests now also record the SHA-256 of `data/manifest.json` and `data/fma_calibration_v1.json` at run time (`manifest.data_provenance`). No simulation, metric or guard code changed; the frozen protocols, configs and data files are untouched and their hashes still match `research/freeze.json`.
